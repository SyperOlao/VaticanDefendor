# Рендеринг и оформление

Обязательные инструкции для Assets. Область действия, даты, исключения и разрешения исходного Assets/AGENTS.md сохранены.


### Исходный раздел: 5. Unity lifecycle и ресурсы; строка 131

- `OnValidate` выполняет локальную проверку, без установки пакетов, перестройки сцены и изменения сессии. Не уничтожай общие material/mesh/asset как собственный runtime-экземпляр.


### Исходный раздел: 10. Сериализация и безопасная миграция; строка 188

- В `Presentation` есть шейдеры. Сохраняемый контент не удаляется вместе с архитектурой; проверяй ссылки префабов, основной и recovery-сцен.

Этот раздел не поручает самостоятельно начинать удаление или перенос файлов.

Локальный Windows-стенд без Docker запускается через `backend/scripts/start-windows.ps1`: существующий PostgreSQL проекта, API и выделенный сервер. Launcher использует выбранный ContentRelease и существующие `.runtime`-секреты; не пересоздаёт базу, не пересобирает Unity и не завершает посторонние процессы. Успех требует готовности БД/API и регистрации серверной сборки с текущими версиями контента и протокола.



### Исходный раздел: Скелетные персонажи Shadow Ages; строка 231

- RenderMeshArray в 6.6 содержит хост с подсчётом ссылок. Если System хранит массив между удалением и повторным созданием сущностей, она вызывает Retain сразу после создания и Release при уничтожении; одной C#-копии структуры недостаточно. Иначе удаление последней shared-component ссылки ломает следующий reconnect/FX spawn.
