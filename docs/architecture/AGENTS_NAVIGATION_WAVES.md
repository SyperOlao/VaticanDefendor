# Этап 6: Agents, Navigation, Waves

## Владение и порядок

Один dedicated server ведёт один `RunSession`. `RunSimulationTime` и `RunRandomState` — отдельное состояние этой сессии; состояние генератора хранится как ECS-компонент для будущего сохранения. `WaveScheduleSystem` планирует появления по времени симуляции и лимитам `WaveScheduleDefinition`. `ServerWaveSpawnSystem` создаёт интерполируемые `TargetGhost` с серверными компонентами агента. `EnemyDecisionSystem` выбирает живого героя и записывает навигационную цель и `EnemyAttackIntent`. `NavigationFlowSystem` вычисляет общее поле направлений; `EnemyMovementSystem` меняет позицию. `EnemyCombatResolutionSystem` принимает намерение, проверяет цель и дистанцию до и после замаха, применяет урон, recovery и лимит одновременных замахов. Combat остаётся владельцем здоровья и смерти; `CombatResolutionSystem` начисляет награду через `RunEconomySession` один раз. `EnemyDeathCleanupSystem` удаляет мёртвый ghost после задержки из определения.

Клиент не выполняет AI и не хранит собственную симуляцию врагов. Он читает подтверждённые интерполируемые ghost и создаёт из них модели и маркеры для двух камер сохранённого layout. Главный герой остаётся предсказываемым Netcode ghost.

## Навигация

Сохранённая арена плоская. Для неё выбран квадратный grid 15×15 с шагом 2,4 м и общим BFS flow field к герою. `ArenaNavigation.asset` содержит 24 круговых препятствия, снятых с сохранённых Pine/Rock в `ActiveCombat.unity` явной Editor-командой. Они становятся непроходимыми ячейками. Запросы `NavigationObstacleRequest` с устойчивым положительным `StableId` добавляют, обновляют и удаляют динамические препятствия. Этот контракт предназначен для строительства этапа 7; неизвестная геометрия и превышение лимита вызывают явную ошибку.

Перестроение поля ограничено числом ячеек за tick. Новое поле готовится отдельно, после чего заменяет активное; перемещение цели инициирует перестроение только после заданного интервала и порога смещения. Каждый враг читает общее поле и проверяет проходимость следующей позиции. Индивидуальный поиск пути каждый кадр отсутствует. Grid и простая круговая аппроксимация пригодны для текущей арены; точные коллизии между врагами, узкие проходы и произвольная будущая геометрия потребуют отдельной проверки. Persistent `NativeArray` и `NativeList` принадлежат `NavigationFlowSystem` и освобождаются в `OnDestroy`.

## Настройка

`EnemyWeakAgent.asset` задаёт скорость, разброс, дальность/урон/время удара, дистанцию построения, задержку удаления и предел одновременных замахов. `WeakEnemyWaves.asset` задаёт размер волн, интервалы, предел одновременно живых и появления за tick. `ArenaNavigation.asset` задаёт геометрию и бюджет перестроения. Все определения проходят `ContentReleaseBuilder`; сессия получает снимок release при старте. `VaticanDefendor > Stage 6 > Prepare Content` создаёт недостающие ассеты и выбирает release; `Refresh Static Obstacles From Saved Scene` явно переснимает геометрию после изменения сцены.

## Проверка и измерительный стенд

В Unity Editor: `VaticanDefendor.Editor.Stage6Verification.Verify`. Раздельные Development Build: `VaticanDefendor.Editor.NetworkPrototypeBuild.BuildServer` и затем `BuildClient`. Обычная волна и бой через отдельные процессы: `powershell -File backend/scripts/verify-waves.ps1`. Для трёх уровней нагрузки после сборок: `powershell -File backend/scripts/measure-waves.ps1` (`small` 32, `medium` 128, `large` 512 врагов; параметр `-DurationSeconds` задаёт длительность). Скрипты запускают отдельные процессы сервера и клиента через Unity Transport и требуют подтверждённое подключение. `-vdLoadLevel` действует только в явном development identity режиме и меняет параметры одной измерительной сессии; числа уровней не являются заявлением о поддерживаемой нагрузке.

`[ServerTick]` сообщает среднюю и максимальную длительность участка server simulation group за последние 5 секунд и число живых врагов. `[ClientDisplay]` сообщает длительность клиентского кадра после открытия игрового экрана в графическом клиенте; headless запуск не измеряет отображение. Для оценки CPU, GC, сетевого трафика и frame time на целевых устройствах нужен этап 11.
